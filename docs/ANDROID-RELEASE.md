# Android Release Guide

Сборка подписанного AAB для React Native приложения (`mobile/`) и публикация в Google Play.

> Переписан 2026-08-30. Предыдущая версия описывала сборку через `cargo tauri android build`
> и была удалена вместе с Tauri-слоем. Историю можно посмотреть:
> `git show f60b2aa:docs/ANDROID-RELEASE.md`.

---

## 0. Чего сейчас нельзя

**Публиковать нельзя** до решения об имени пакета.

`applicationId` приложения — `com.rustok` (`mobile/android/app/build.gradle`), а черновик в Play
Console заведён как `com.rustok.app`. Они не совпадают, и загрузка будет отвергнута. Плюс в
`CLAUDE.md` записан запланированный ренейминг проекта.

**Имя пакета в Play нельзя изменить никогда** — после первой публикации листинг привязан к нему
навсегда, смена означает новое приложение без установок, отзывов и истории. Поэтому:

- собирать и проверять пайплайн — можно прямо сейчас;
- нажимать «загрузить» — только после того, как финальное имя выбрано.

Воркфлоу устроен так, что случайно это сделать нельзя: `upload_to_play` по умолчанию `false`.

## 1. Ключ подписи

### 1.1 Где он

Ключ существует как секрет репозитория `ANDROID_KEYSTORE_BASE64` (заведён 2026-04-26). Локальной
копии на машине разработчика на 2026-08-30 **не найдено** (`~/Keys/` отсутствует), а прочитать
секрет обратно из GitHub нельзя.

Пока приложение не опубликовано, потеря ключа ничего не стоит — генерируется новый и заменяется
секрет. После первой публикации восстановление upload key возможно только через обращение в
Google. **Проверить наличие резервной копии стоит до публикации, а не после.**

### 1.2 Создать новый, если нужно

```bash
keytool -genkey -v \
  -keystore rustok-release.keystore \
  -alias rustok \
  -keyalg RSA -keysize 2048 -validity 10000
```

Хранить вне репозитория, например `~/Keys/rustok-release.keystore`.

### 1.3 Локальная релизная сборка

```bash
cd mobile/android
cp keystore.properties.example keystore.properties
# заполнить storeFile / keyAlias / password
```

`keystore.properties` закрыт `.gitignore` и коммититься не должен; `.example` — безопасен.

Без этого файла **release-сборка падает** с сообщением, что делать. Это сделано намеренно: раньше
она молча подписывалась debug-ключом и выдавала артефакт, который Play отвергает. Debug-сборки без
файла работают как обычно.

### 1.4 Секреты для CI

| Секрет | Что |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore, закодированный base64 |
| `ANDROID_KEY_ALIAS` | alias ключа (`rustok`) |
| `ANDROID_KEY_PASSWORD` | пароль keystore и ключа |
| `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` | **отсутствует** — нужен только для загрузки, см. §4 |

```bash
base64 -w0 ~/Keys/rustok-release.keystore
# вставить в секрет ANDROID_KEYSTORE_BASE64
```

## 2. Сборка через CI

**Actions → Android Release Build → Run workflow.**

| Вход | Что |
|---|---|
| `version_code` | обязателен, целое. Должен быть **больше** предыдущего на треке |
| `version_name` | видимая версия, например `1.0.0` |
| `upload_to_play` | по умолчанию `false` — не включать до §0 |
| `track` | `internal` по умолчанию |

Результат — артефакт `rustok-android-release-aab`.

### Про `version_code`

Передаётся явно, а не вычисляется. `github.run_number` не подходит: он сбрасывается при
пересоздании воркфлоу и никак не связан с `versionName`. Запрос последнего значения через Play
API возможен, но требует сервисного аккаунта, которого пока нет — поэтому автоматизировать это
имеет смысл после §4, а не до.

Play отвергает загрузку, если `versionCode` не выше предыдущего на треке. Держите счётчик в
одном месте и увеличивайте вручную.

## 3. Локальная сборка

```bash
cd mobile/android
JAVA_HOME=<путь к JDK 17> ./gradlew bundleRelease \
  -PversionCode=2 -PversionName=1.0.1
```

AAB окажется в `mobile/android/app/build/outputs/bundle/release/`.

> **JDK строго 17** — AGP другую не примет. На машине, где писался этот документ, стоял только
> JDK 25, поэтому релизная сборка локально не проверялась ни разу: единственная площадка
> валидации — CI.

## 4. Публикация

### 4.1 Сервисный аккаунт (нужен только на этом шаге)

JSON выпускается **не в Play Console**, а в Google Cloud Console; Play Console только выдаёт
этому аккаунту права на приложение.

1. Play Console → **Настройки → Доступ к API** — убедиться, что проект Google Cloud связан.
2. Google Cloud Console → **IAM → Сервисные аккаунты** → создать (роли проекта не нужны) →
   **Ключи → Создать ключ → JSON**.
3. Убедиться, что включён **Google Play Android Developer API**.
4. Play Console → **Доступ к API** → выдать аккаунту права на релиз в нужные треки.

```bash
gh secret set GOOGLE_PLAY_SERVICE_ACCOUNT_JSON --repo temrjan/rustok < ~/Downloads/<файл>.json
```

Скачанный файл после этого удалить — это приватный ключ публикации.

### 4.2 Первая загрузка — только вручную

Google не принимает через API **первую** сборку нового приложения. Один AAB нужно загрузить
через веб-интерфейс Play Console (**Тестирование → Внутреннее тестирование → Создать релиз**),
и лишь после этого API начнёт работать.

### 4.3 Play App Signing

Google держит финальный ключ подписи, разработчик загружает upload-ключом (§1). При утере
upload-ключа его можно сбросить через поддержку — в отличие от финального.

## 5. Поддерживаемые архитектуры

`arm64-v8a` и `x86_64`. 32-битные устройства **не поддерживаются** (решение 2026-08-30,
`docs/PHASE-2-CONSTRAINTS.md` P2) — Play пометит приложение несовместимым с ними.

Два списка обязаны совпадать:

- `packages/react-native-rustok-bridge/ubrn.config.yaml` — под что компилируется Rust;
- `mobile/android/gradle.properties` (`reactNativeArchitectures`) — под что собирается приложение.

Если в одном списке появится ABI, которого нет в другом, AAB получит сплит **без Rust-библиотеки**,
и на таких устройствах приложение упадёт на `UnsatisfiedLinkError`. Возврат 32-бит требует ещё и
Rust-таргета `armv7-linux-androideabi` в `.github/workflows/`.
